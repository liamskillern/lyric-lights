# Lyric Lights on Android (Google Play)

The Android app is a **Trusted Web Activity**: a thin Android shell that opens the live site
(`https://liamskillern.github.io/lyric-lights/`) full screen in Chrome. This means:

- **Website updates reach the app automatically.** Push to `main` and the app shows the new version the next time it opens. A new Play release is only needed to change the app shell itself (name, icon, version).
- **Spotify login works,** because it runs in real Chrome rather than a WebView. Login pages such as Google sign-in refuse to run inside embedded WebViews.
- **The app is small:** about 1.8 MB.

## Know this first

- **Going public takes at least 14 days.** Google requires personal developer accounts created after Nov 13, 2023 to run a **closed test with at least 12 testers who stay opted in for 14 days in a row** before applying for production. [Internal testing](https://support.google.com/googleplay/android-developer/answer/9845334) (just you, up to 100 people) has no wait.
- **Spotify only lets a few accounts log in.** Since February 2026, Spotify's Development Mode needs the **app owner to have Spotify Premium** and allows **5 allowlisted users per app**. Extended quota is for businesses. So:
  - Spotify login works for you and the people you add under *User Management* in your Spotify app.
  - Everyone else can use the demo, or create their own Spotify developer app (they need Premium) and paste its Client ID on the setup screen.
- **Login lasts until the app closes.** Your login is kept per window by design (a security choice; see the report). Reopening the app takes one tap on *Connect Spotify*.
- **Beat sync on phones uses the microphone.** Using the computer's sound only works in Chrome or Edge on a desktop.

## 1. Try it on your Pixel today (optional)

- **Installable web app:** open <https://liamskillern.github.io/lyric-lights/> in Chrome, then ⋮ → **Install app** (or *Add to Home screen*). It opens full screen from your home screen.
- **The Android app itself:** download `lyric-lights-1.0.0.apk` on the phone, open it, and allow *Install unknown apps* for the app you opened it with.
  - Until step 2 is done, a thin address bar shows at the top. That bar is how Android says it hasn't verified the site yet.
  - Before installing the Play version later, uninstall this one. They're signed with different keys, so Android won't replace one with the other.

## 2. Prove the app owns the site (once)

Android hides the address bar only if `https://liamskillern.github.io/.well-known/assetlinks.json` lists the app's signing fingerprints. Only a repo named exactly `liamskillern.github.io` can publish at that address.

1. On GitHub, create a **public** repo named **`liamskillern.github.io`**. Leave it empty.
2. Ask Claude to push the prepared files to it: `assetlinks.json`, `.nojekyll`, and a README.
3. In that repo: **Settings → Pages → Source: Deploy from a branch → `main` / root → Save.**
4. Check that <https://liamskillern.github.io/.well-known/assetlinks.json> shows the JSON.

**Keep that repo free of HTML and scripts.** All your GitHub Pages sites share one origin, so a script published there could read what Lyric Lights stores in the browser.

## 3. Create the app in Play Console

**Home → Create app:**
- App name: `Lyric Lights`. Never put "Spotify" in the name; Spotify's terms don't allow it.
- Default language: English (United States)
- App or game: **App**
- Free or paid: **Free**
- Accept the declarations → **Create app**

## 4. Upload to internal testing

1. **Test and release → Testing → Internal testing → Create new release.**
2. When asked about app signing, keep **Google-managed app signing** (the default). Google then holds the key the app is actually signed with, and your key is only for uploading.
3. Upload `lyric-lights-1.0.0.aab`. Release name: `1.0.0`. Release notes: `First release.`
4. **Next → Save → Testers:** create an email list with your own Google account → copy the **opt-in link**, open it on your Pixel, and install from Play.

## 5. Send Claude the Play signing fingerprint

**Test and release → Setup → App signing** (*App integrity → App signing* on some accounts). Copy the **SHA-256 certificate fingerprint** under **App signing key certificate**. It's public information, not a secret. Claude adds it to `assetlinks.json`, so the Play-installed app opens without an address bar.

**Data safety (suggested answers; you make the final call).** Play counts data as "collected" when the app sends it off the device, even if the developer never receives it. Data processed only on the device doesn't count.
- *Does your app collect or share any required user data types?* **Yes**
  - **App activity → Other actions** (the title, artist, album and length of the song playing): **shared** with LRCLIB to look up lyrics. Processed ephemerally. **Required**. Purpose: **App functionality**.
- The rest isn't collected:
  - **Spotify login** happens on Spotify's own page. The app never sees your password, and tokens stay on the device.
  - **Microphone audio** is analyzed on the device and never sent anywhere.
- *Is all user data encrypted in transit?* **Yes** (HTTPS only)
- *Can users request that their data is deleted?* The developer stores nothing. Say so, and point to "Log out" and clearing the app's data.

## 8. Closed test, then production

1. **Testing → Closed testing → Create track** (or use *Alpha*) → upload the same AAB, or promote the internal release.
2. Add **at least 12 testers** (an email list or a Google Group) and share the opt-in link. Each tester opens the link, taps *Become a tester*, and installs from Play.
3. Keep at least 12 opted in for **14 days in a row**. Testers can use the demo; Spotify login only works for the people you allowlisted.
4. **Dashboard → Apply for production** and answer Google's questions about your test. After approval, create a production release.

## Updating the Android app later

Website changes need nothing here. To change the shell (icon, name, colors, version):

1. Edit `android/twa-manifest.json`, then bump `appVersionCode` (and `appVersionName`). In `android/app/build.gradle`, match `versionCode`/`versionName`.
2. Build and sign. This needs JDK 17 and Android SDK 36; Android Studio includes both. The live wallpaper bundles a copy of the site, so build that first.
   ```bash
   npm run build:android
   cd android
   ./gradlew bundleRelease
   jarsigner -keystore lyric-lights-upload.keystore -sigalg SHA256withRSA -digestalg SHA-256 app/build/outputs/bundle/release/app-release.aab upload
   ```
3. Upload the AAB as a new release.

Regenerate the whole project from `twa-manifest.json` with `npx @bubblewrap/cli update` (it downloads the icons from the live site).

**Security settings that a regenerate undoes.** Bubblewrap rewrites `android/` from its templates, so after `bubblewrap update` put these back (`npm test` fails until you do):
- `android:allowBackup="false"` in `AndroidManifest.xml`, so Android's backup doesn't copy the app's data off the phone.
- The link check in `LauncherActivity.java` (`isLyricLightsUrl`). Any app on the phone can start Lyric Lights with a link of its choosing; this only lets `https://liamskillern.github.io/lyric-lights/…` through and opens the home page for anything else.
- `mavenCentral()` instead of `jcenter()` in `android/build.gradle`. JCenter is shut down and only kept as a read-only mirror, and every extra repository is one more place a fake package could come from.

## Troubleshooting

| Problem | Fix |
|---|---|
| An address bar shows at the top of the app | The site link isn't verified. Check that `assetlinks.json` is live and lists the fingerprint of the key that signed the installed copy: the upload key for the APK, the Play key for Play installs. Then uninstall and reinstall the app; Android re-checks at install. |
| "App not installed" when installing the APK | A copy signed with a different key (for example, from Play) is already installed. Uninstall it first. |
| Spotify login says 403 | Add the account under **User Management** in your Spotify developer app. The owner needs Premium. |
| Blank screen offline | Expected: the app needs the internet. It shows a "You're offline" page with *Try again*. |
